# 留存诊断与自我迭代闭环（Retention Diagnosis Loop）

## 使用入口

用户可提供产品目标、使用节奏、事件定义、分群指标、实验或案例。
只有聚合图表时先给描述与竞争解释，标明缺少的口径和证据；不编造用户级记录或因果结论。
诊断与方案不自动授权线上实验、数据导出、策略发布或联系用户；用户既有授权在明确范围内有效。

## 先判断留存是否适用

- 一次性任务：优先看合格完成、交付时间、后续问题和推荐 / 再需求时选择。
- 低频产品：按合理需求周期看复购、复发、回访，不能直接套日活或 D7。
- 持续型服务：留存可作为信号，但仍需分辨价值、获客、价格、季节性和替代品影响。

「价值 → 留存 → LTV」是可检验假设，不是通用单向因果律。
在价值底线内优化回访、提醒或付费可以合理；指标变好本身也不能证明价值改善。
服务成功后减少使用可能是正向结果，流失需结合任务目的解释。

## 三角验证：多源证据框架

| 视角 | 观察什么 | 局限 |
|---|---|---|
| 过程证据 | 行为、工具执行、接触频率、漏斗 | 过程顺利不等于结果正确 |
| 实际结果 | 用户或组织要完成的事、客观效果、后续问题 | 可能有延迟、混杂与测量误差 |
| 价值评价 | 用户感受、付费方及其他受影响方的评价 | 主观满意不替代客观质量，也可能无法即时获取 |

按领域选择证据，不机械要求三层同时改善或连续两次就算因果成立。
矛盾时列竞争解释、测量延迟和缺口；继续无争议分析，暂停依赖未解决判断的发布。
分别报告观察到的变化、因果解释的可信程度、是否达到实验与发布条件。

## 领域配置

分析前定义与本次决策相关的配置，不要求不适用字段：

- 产品节奏、任务完成或合格使用事件、受益者和观察周期。
- 主要结果、代理指标、质量 / 伤害护栏，指标方向和最小有意义变化。
- 人群、渠道、暴露 / 实验单位、事件与归因口径、数据完整性。
- 可调整策略、现有授权、发布责任方、停止与恢复条件。
- 数据可见范围、保留期、回放与删除要求。

例如电商复购先明确品类的合理购买周期；退款、解决问题和复购一起解释，不把加购率或 NPS 单独当成价值。
无需为每个领域重复主流程，具体测量方法按需读取 [测量与实验](references/measurement.md)。

## 诊断到改进

1. **确认信号可信**。查事件版本、去重、延迟、成熟窗口和指标定义，再看是否真有变化。
2. **按相关维度比较**。检查渠道 / 人群构成、季节性、产品变动和数据缺失；分层后样本不足时保留不确定性。
3. **生成竞争解释**。获客不匹配、价值交付、需求频率、价格和测量问题都可能造成相同曲线；不能凭某渠道差就直接改素材。
4. **设计最小验证**。选择案例核查、日志回放或受控实验。实验写清单位、主要结果、效应门槛、样本依据、运行周期和停止规则；不默认 5% 流量或 7 天适合所有产品。
5. **区分记录与生效**。经验、个人偏好与群体策略按 [记忆生命周期](references/memory-lifecycle.md) 处理；失败也记录，不能只保存获胜策略。
6. **反馈到正确责任方**。运行配置缺陷给 Harness 维护方；价值、规范或评价标准问题给种子责任方，运行 Agent 不自行降低目标或扩权。

自动调整仅限明确授权的策略范围。运行预算、权限、评价门槛等如需变更，应使用对应治理和发布流程，不能通过「学习」绕过。
批准种子及其变更状态见 [种子契约](../seed-extraction/references/seed-contract.md)；依赖不可用时给出建议和缺口，不假定可发布。

## 数据与健康线

事件用 event_id 去重；用户 / 租户、任务 / trace、实验暴露和 cohort 分别建关联。
时间戳与渠道是时间 / 属性信息，不能默认当成多张表的唯一连接键。粒度、连接基数、归因窗口见测量参考。
先建立可比、成熟且样本充分的基线，再选择分位数、控制图或其他方法。
没有通用 D1/D7/D30 百分比；2–4 周也不能为新上线产品提供成熟 D30 基线。
样本不足时输出描述性变化、区间、案例与待测假设，不假装「没有统计结论」就什么也不能交付。

## 风险事件与恢复

实验或策略触发预先定义的伤害护栏时，暂停受影响的实验 / 策略，并按协议核查影响。
协议定义事件等级、影响范围、接收责任方、响应时限、需要停用的动作和恢复条件；是否扩大暂停由可见影响与不确定性决定。
共享组件受损可能需要扩大范围，但单一事件不必自动停止所有租户的无关操作。
上线自动实验前需有与其风险相称的停止、回滚与责任机制；已有机制可复用。

## 输出与示例

输出：指标适用性、数据口径、已知事实、竞争解释、证据缺口、验证设计、记忆 / 发布路径。
把「建议采取」「已获授权」「已执行」「已验证」分别写清。

输入：「迁移助手的 D7 很低，但迁移成功率高，售后问题很少。」
结果：先核对服务是否一次性；不直接启动留存拉升实验。若缺少用户后续结果，提出合适观察窗口或抽样核查，保留不确定性。
