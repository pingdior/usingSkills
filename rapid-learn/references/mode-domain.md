# domain 模式 · 项目 / 方向 / 论文 / 代码仓库

适用：成人自学一个开放领域。典型场景——技术调研（如 HRV 检测方法、自主神经系统指标）、读懂一个开源仓库、啃一组论文、理解一个行业或商业模式、上手一个新工具。

## 开场信息卡（缺什么问什么，一次问完）

| 项 | 说明 | 例 |
|---|---|---|
| 学习对象 | 方向 / 项目名 | "PPG 信号算 HRV 的完整链路" |
| 交付物 | 结束时必须做出来、可检验的东西 | "能给投资人 3 分钟讲清 + 回答 3 个追问" / "跑通一个 demo" / "一页技术选型结论" |
| 已有基础 | 相关的已会内容 | "懂信号处理基础，不懂心血管生理" |
| 原始资料 | 论文 / 文档 / 仓库路径 / 无 | 本地路径或粘贴内容 |
| 总时长 | 默认 4 小时 | 也可 2 小时压缩版 |
| 学习类型 | A 理解型（讲清楚）/ B 动手型（做出来）/ C 查证型（读懂资料回答问题） | 决定阶段 3 的做法 |

交付物如果模糊（"了解一下""掌握"），必须帮用户改写成可检验的形式再开始。

## 时间分配（4 小时）

| 阶段 | 时长 | 做什么 |
|---|---|---|
| 0 定标 | 15 min | 3 道诊断题：1 道概念、1 道应用、1 道"你会怎么判断"。据结果调整阶段 2 的粒度 |
| 1 地图 | 30 min | ①那"一句话"核心洞见（理解它其他就通了）；②5–8 个关键概念 + 它们之间的关系（用文字箭头或 mermaid 图）；③**明确列出可以完全忽略的内容**及理由 |
| 2 拆核心 | 60 min | 每个关键概念：日常类比、零术语讲一遍 → 再给正式说法 → 问 1 个只有真懂才能答的问题 |
| 3 实战 | 90 min | 按学习类型分流（见下） |
| 4 压力测试 | 30 min | 5 个陷阱题（看似简单、暴露浅理解，每题后指出暴露了什么缺陷，不手软）+ 费曼讲解（对 10 岁孩子讲，用了自己不懂的词、跳步、过度简化时立即打断） |
| 5 沉淀 | 15 min | 用 `assets/templates/domain-note.md` 生成笔记 |

2 小时压缩版：0→10、1→20、2→30、3→40、4→15、5→5。

## 阶段 3 分流

- **A 理解型**：给一个真实情境（例如"投资人问：为什么不用 Apple Watch 的数据？"），让用户回答；不提醒容易错的地方；答完再按硬规则 4 追问。
- **B 动手型**：拆成 3–5 个可运行的小步骤，每步让用户先自己写/做，卡住时只给提示不给完整代码；每步都要实际运行验证（能跑命令就跑，不纸面判断）。
- **C 查证型**：先让用户写下 3 个自己想弄清的具体问题，再**带着问题去原始资料里找答案**，要求定位到具体段落 / 文件 / 函数；AI 只做向导，不替读。

## domain 专属规则

1. **有原始资料时**：结论必须能指回资料位置（论文节号、文件路径:行号）；资料没说的标"资料外推断"。
2. **医学 / 健康类内容**（HRV、抑郁、生理指标等）：区分"研究证据级别"（综述 / RCT / 单篇观察性研究 / 厂商白皮书），不把相关性说成因果；涉及产品宣称时提示合规边界。
3. **代码仓库**：地图阶段先给"目录 → 职责"表 + 一条主调用链路，不逐文件讲。
4. **数字和参数**：没有出处的数字不给；给范围时说明来源条件。
