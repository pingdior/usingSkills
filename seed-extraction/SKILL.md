# 种子提炼（Seed Extraction）

## 使用入口

用户可提供业务范围、案例、合同、运行记录或已有规则，请求「从这些材料提炼种子」。
先复用材料；资料不足时交付带缺口的草稿，必要时转入交互收敛。用户仅要求评审时，不替其发布规则或修改运行系统。

## 种子是什么

种子是在明确业务范围与时间尺度内，描述**价值目标、必要结构、约束与反馈依据**的最小可维护契约。
保留会影响决策的内容，也保留有理由的冗余和安全余量；不要求「删除任何一条，价值必然崩溃」。
SOP、工具选型和当前最优做法通常是策略，不能仅因被长期使用就成为核心约束。

四部件是文档级组织方式：

- **价值指向**：为谁带来什么改变，主要目标、次级目标与不可交易的底线是什么。
- **必要结构**：参与者、对象、状态、资源、责任与证据如何关联。
- **约束**：在什么条件下适用，依据是什么，如何检查，谁有权修改。
- **反馈依据**：成功、失败与副作用如何被观测，判据有哪些局限。

## 先分类，再验证

| 条目类型 | 需要的依据与检查 | 不应作的推断 |
|---|---|---|
| 经验性约束 | 观察或证据来源、作用机制、适用范围、反例与竞争解释 | 常见关联等于因果，或某次失败证明普遍必然性 |
| 规范性约束 | 法律、合同、组织规则或明确授权的来源；适用范围、违规检查与修订权限 | 违反它仍赚钱，因此可以取消它 |
| 价值目标 | 受益者、结果定义、冲突时的优先级或允许范围 | 只能有一个目标，或代理指标完全不可用 |
| 策略 / SOP | 相对替代方案的效果、成本、适用条件与撤回方式 | 有效做法等于唯一必要路径 |

经验性条目可以是概率关系；证据不足时保留为假设，不把「可能增加风险」升级成「必然失败」。
规范性约束以违反条件和合法变更条件检查，不要求用获利反例推翻。

## 五步提炼法（按材料缺口取用）

1. **界定一次价值实现或一个可观察周期**。明确起止、受益者、付费方及其他受影响方；持续型服务可用周期，不强行缩成一单。已有明确边界时直接引用。
2. **从正常、失败和例外案例找候选关系**。区分直接观察、用户陈述、分析推断和待验证假设。缺少案例只说明当前证据不可得，不能推断企业阶段或用户能力。
3. **检查机制与替代解释**。资源、信息、激励、责任、可验证性是常用线索，允许其他机制或机制未明。对经验性条目比较跨组织、跨技术及反例；对规范性条目核对来源与适用性。
4. **写成能指导决策的条目**。写清类型、范围 × 时间尺度、关系或要求、来源、适配的检查方式与变更权。将实施策略和待验证假设单列。
5. **用未参与提炼的案例检查**。观察能否识别失败、容纳合法可行的替代方案、解释边界。真实保留案例与构造场景分别标注；模型构造的场景不能充当真实业务验证。

优先追问会改变结论的缺口。多目标冲突时，先守住约束，再说明主要目标与次级优化目标如何取舍。
准确率、费用、时长等可能直接构成价值，也可能只是代理指标，需按任务解释。

## 证据、稳定性与修改

- 分别记录**证据状态、变化条件、修改权限与改变后的损失**；不按物理、法律、经济、认知给出通用稳定性排序。
- 事实与策略可随证据更新；规范变更需要有效授权。目标和评价标准由治理责任方维护，运行任务的 Agent 只能提出修订建议。
- 用户既有授权在其范围内有效，不要求每次重复确认；Agent 不能通过给产物标记状态来授予自己批准权。
- 提示文字不能强制权限。落地时将重要约束映射到可执行校验或工具权限，并标注仍无法自动验证的部分。

## 交付与衔接

产出四部件、条目依据、假设 / 策略、缺口和建议验证动作。不要为满足格式编造证据、审批人或版本。
正式种子状态、最小交接字段及升级规则以 [种子契约](references/seed-contract.md) 为唯一维护来源；生成或评审正式交接物时读取它。

后续技能消费同一份带版本的种子：seed-convergence 补足证据，digital-life-service-design 设计服务，harness-design 映射运行约束。
未安装其他技能时，仍可交付当前分析与缺口，不自动安装或假定它们可用。

## 示例与质量检查

输入：「客服必须当天响应，这是行业铁律。」

动作：查合同是否承诺当天响应；另查不同人群、时段和问题下延迟与损失的证据。
产物：合同要求归为规范性约束；「延迟增加某类客户流失」作为有范围的经验判断；「所有客户统一当天响应」作为可比较的服务策略。

交付前检查：条目类型是否正确；范围是否明确；是否把陈述当事实；是否保留可行替代方案；约束是否能检查；未知是否仍被如实标记。
只加载与当前判断有关的材料，保留来源引用；不以固定行数推断模型是否会遵守规则。
