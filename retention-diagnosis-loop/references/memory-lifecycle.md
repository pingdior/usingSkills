# 记忆生命周期与共同账本

本文件是个人记忆、经验候选与策略发布路径的维护来源，供服务设计与诊断技能共同引用。
Memory 写入、检索使用、策略发布与模型训练是不同动作，不能以「已记住」暗示全部生效。

## 按内容与作用范围分流

| 内容 | 依据与生效路径 | 边界 |
|---|---|---|
| 用户明确表达的个人偏好 | 在既有记忆授权和个人范围内更新；记录来源，支持查看 / 撤销 | 不擅自扩大到租户或其他用户；明确偏好不必走群体 A/B |
| Agent 推断的事实或偏好 | 标记推断与不确定性；按影响决定是否需确认，设置失效条件 | 不当成用户授权；高影响决策不依赖未经核验的敏感推断 |
| 当前任务的操作状态 | 由运行时持久化，按 [运行契约](../../harness-design/references/runtime-contract.md) 恢复 | 不因被存储就变成跨任务规则 |
| 可复用经验 / 群体策略 | candidate → 离线检查或回放 → 适配的受控试验 → 批准 / 发布 | 低风险更新可使用既定批准政策；未经覆盖不能自动推广 |
| 目标、核心约束、权限或评价门槛 | 向责任方提交修订，遵循 [种子契约](../../seed-extraction/references/seed-contract.md) 与对应运行治理 | 运行 Agent 不得通过记忆改写上层规则 |

个人偏好所需的记忆授权尚未建立时，先按当前对话使用，说明持久保存缺口；不声称已跨会话记住。
确立某项偏好也不代表允许执行其涉及的外部操作，例如「偏爱邮件」不自动授权发送邮件。

## 最小记录与关联

通用字段按需要保存：record_id、kind、scope、source_ref、evidence_status、created_at、valid_until、status、derived_from。
scope 明确 tenant / user / task 及对应标识；缺失租户或用户范围时不能默认共享。
策略再关联 policy_id / version、seed_id / version、experiment_id、判据版本及发布依据。
用户偏好无需虚构实验号；缺失或不可量化的置信度如实说明，不默认填数字。

操作 trace、用户事件和策略有各自 ID，通过显式引用连接；「共同账本」不要求所有对象使用同一个主键。
检索时检查授权范围、有效期、来源撤销和适用条件；过期或被撤销记录不能继续影响新任务。

## 发布、回退与失效传播

- 经验候选不默认影响生产策略；对用户明确偏好及任务状态使用上表的专门路径。
- 发布记录作用范围、版本、判据与批准依据；现有审批覆盖时引用它，不反复索取。
- 群体策略的离线回放、试验和人工批准强度随风险调整，但调整政策本身须有授权。
- 种子变更、证据撤销、用户删除或期限届满时，查 derived_from 依赖，停用或重审受影响记忆和派生策略。
- 用户删除应覆盖原文、向量、缓存、快照与可识别派生记录；不可逆聚合或法定保留的例外需事先定义并说明，不能谎称全部可删除。
- 停用策略并不撤销已经发生的外部动作；恢复 / 补偿遵循运行契约。

## 失败样本与隐私

为了回放，保存本次判定所需的输入引用或快照、环境 / 工具 / 判据版本和结果。
先明确原始数据是否允许保存、在哪里保存、谁能解密与使用、何时删除。

- 明文不出设备的部署：端侧保存与回放；服务端可接收批准的聚合结果或去敏模拟样本。
- 受控服务端部署：使用范围受限、加密、可审计、有保留期的快照；不把加密当作服务器不可见。
- 快照不可得时：记录可复现性缺口和允许保留的最小元数据；构造案例只能支持机制测试，不能冒充原始事故重现。

向量和去标识数据也可能泄露身份或状态；安全的日志、跨表关联、密钥备份和访问范围需要一起考虑。
严格隐私可能降低归因和回放能力，交付时说明取舍，不用「脱敏了」掩盖未知。
