# 追问弹药库（Question Bank）

`SKILL.md` 只放收敛序与判据；这里放**具体怎么问**。按轮次取用，不要一次性全抛给用户。

---

## 通用追问阶梯（任何约束都能套用）

| 招式 | 问法 | 用来打掉什么 |
|---|---|---|
| 省略式 | 如果省掉这一步，**具体**会在哪里出问题？ | 惯例（"一直这样做"） |
| 反事实式 | 有没有哪次没这么做？结果如何？ | 伪约束 |
| 主体式 | 这一步是谁在承担后果？没人承担会怎样？ | 责任真空 |
| 时间式 | 五年前也这样吗？十年后还会这样吗？ | 稳定性误判 |
| 边界式 | 什么情况下这条会失效？ | 过度泛化 |
| 成本式 | 为了满足它，你们放弃了什么？ | 隐藏的取舍（往往才是真约束） |
| 信号式 | 当时他看到了哪几个信号才这么判断的？ | 隐性判据（老师傅的经验） |

**铁律**：连续追问直到答案落到五类机制。用户给出"对策"时，把对策剥掉，问它想防的是什么。

---

## 第 0 轮 · 框边界（4 问）

1. 这次价值实现**从哪一刻开始、到哪一刻结束**？
2. **谁付钱**？付钱的人和使用的人是同一个吗？（不同 → 存在两套价值标准）
3. 如果这次没做成，**最坏的结果**是什么？谁承担？
4. 给我讲一个**最近真实发生的完整例子**——要具体的，不要概括。

> 用户仍在谈市场规模/趋势/竞争格局时，一句话收回："这些我先放一边，先看一单。"

---

## 第 1 轮 · 价值指向（4 问）

1. 用户用完这个，**生活/工作中具体发生了什么不同**？
2. 你**怎么知道他真的变好了**？（不要说指标）
3. 如果指标涨了、但他其实没变好，**那会是什么样**？
4. 谁**最**需要它？谁其实**不需要**？

**陷阱识别**：把"效率提升 / 留存提升 / GMV / 满意度 / 转化率"当价值。
追问模板：**"这些涨了，但他真的更好了吗？"**
再追问：**"这个数字是价值本身，还是价值的证据？"**

---

## 第 2 轮 · 必要结构（五问）

1. 谁需要什么结果？谁付钱？
2. 过程中**有什么对象发生了变化**？（状态机）
3. 谁**掌握信息**、作出决定、承担后果？
4. 哪些资源**有限**？哪些承诺**相互冲突**？
5. 最后**凭什么判断结果真的发生了**？

**收敛检查**：逐项问"删掉它，价值链会断吗？"——删掉不断，它就不是必要结构。

---

## 第 3 轮 · 稳定约束（核心轮，占整场一半以上时间）

### 追问阶梯完整示例（从 SKILL.md 移入）

```
用户："必须当天响应。"                          ← 惯例
  ↓ 为什么？省掉会怎样？
"响应慢了客户就找别家。"                        ← 结果，还不是机制
  ↓ 客户为什么会走？他当时缺的是什么？
"他等不起，货压在港口每天烧钱。"                 ← 接近了（经济机制）
  ↓ 这是所有人都会遇到，还是只有部分客户？
"压港的都是我们这样的小客户，大客户有账期。"      ← 机制：激励/资源冲突已现形
```

注意最后一句的后半段"大客户有账期"仍是**策略**，写进种子前要剥掉，只保留"小客户与大客户的账期差异造成资源冲突"这一层关系。

### 五类机制的识别问法

| 机制 | 识别问法 | 典型回答（已到底） |
|---|---|---|
| **资源冲突** | 两个承诺同时来，先满足谁？为什么？ | "运力就那么多，大客户优先" |
| **信息缺失** | 做这个决定时，你**看不到**什么？ | "货到港了才知道破损" |
| **激励冲突** | 谁的**利益**和结果不一致？ | "派单员按单量算钱，不管准点率" |
| **责任无人承担** | 出事了谁负责？**有明确的人吗**？ | "互相扯皮，最后平台兜底" |
| **结果无法验证** | 你怎么知道它**真的**发生了？ | "客户说收到了，但没有签收凭证" |

### 追问弹药（按顺序推进）

1. 「当时为什么必须这样处理？」
2. 「如果省掉这一步，具体会在哪里出问题？」
3. 「这个问题是谁先发现的？他看到了什么信号？」
4. 「有没有一次你们**没**这么做？结果如何？」
5. 「这条规则是谁定的？他当时想防的是什么？」

### 到底了没有

- ✅ 能说出完整链条：**省掉它 → 在 X 环节 → 因为 Y 机制 → 必然出现 Z**
- ❌ 仍是惯例（"行业一直这样"）→ 继续爬
- ❌ 是对策（"所以我们设了 SLA"）→ 剥掉对策，问它防什么
- ❌ 是对人的评价（"客户没耐心""老板要求高"）→ 转问"什么条件下连有耐心的人也会走"

### 第三种异常：过度约束
用户说"我们一直写死/一直全量校验"时，也要反问：**有谁不这么做、却活得很好？** 必要约束与历史包袱在这一问上分家。

## 第 4 轮 · 反馈依据（4 问 + Goodhart 探针）

1. 你怎么知道这件事**做成了**？给我看一条**真实记录**。
2. 反过来：**什么信号出现，说明你们做错了**？
3. 有没有"**看起来都好、但其实已经坏了**"的情况？
4. 谁在盯这个数？他会不会为了让这个数好看而**做别的动作**？

### Goodhart 探针（必问，否则种子会被指标污染）

- 这个指标**可以被刷吗**？怎么刷？
- 如果团队**只**盯这个指标，最坏会变成什么样？
- 有没有"**指标涨了、真实价值掉了**"的历史案例？

> 结论要写进种子：反馈依据必须是"能被观测的**真实结果与失败代价**"，且**明确排除**代理指标。

---

## 第 5 轮 · 反例与分层

### 三检验

| 检验 | 问法 | 打掉什么 |
|---|---|---|
| 跨组织 | 换一家做法**完全不同**的公司，这条还成立吗？ | 公司特有惯例 |
| 跨技术 | 人工换 AI、线下换线上，约束**还存在**吗？ | 技术性临时约束 |
| 反例 | 能找到**绕过它、却仍持续创造价值**的真实案例吗？ | 伪必要约束 |

### 因果归属（决定稳定性层级与修改成本）

| 层 | 来源 | 修改成本 |
|---|---|---|
| 物理 | 运力、容量、地点唯一、时间不可逆 | 几乎永久 |
| 法律/合规 | 监管、合同、资质 | 法规变更时 |
| 经济机制 | 谁担风险、激励结构、现金流 | 激励结构变化时 |
| 认知/习惯 | 客户行为、操作惯例、界面习惯 | 短期可变 |

### 每条收尾必问

> **「什么发现会让你推翻这一条？」**

写不出来的条目 → 退回第 3 轮重做。**没有反例触发器的约束，不是种子，是教条。**

---

## 收尾：用新案例自检

拿一个**用户没讲过**的案例（最好是你自己找的，或他提过的相邻业务），逐条对照：

- 哪几条**提前预警**了某个失败？
- 哪几条**解释了专家**当时为什么这么决策？
- 哪一条**禁止了一个实际可行且创造价值的做法**？→ 那条太紧，要放宽。

三者都有答案，才可交付 v0.1。

---

## 快速开场脚本（可直接照用）

1. 「我们先不聊行业，聊**一次具体的**：最近一次完整做成的业务是哪一单？」
2. 「从头讲一遍，我问的时候你再停。」
3. 「（讲到关键处）这里**为什么必须**这么做？」
4. 「（重复第 3 步，直到落到机制）」
5. 「最近一次**没做成的**、或者**吵起来的**、或者**退了款的**，是哪次？」
6. 「（对失败案例重复第 3–4 步——这条线通常产出最多）」
7. 回读：「我理解的是……，对吗？」
8. 进入下一轮。

> 开场**不要**问"你们行业的核心规则是什么"——那只会得到口号。
