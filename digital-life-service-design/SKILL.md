# 数字生命服务设计（Digital Life Service Design）

## 使用入口

用户可提供服务目标、使用人群、运行环境、现有种子或产品方案。
先确认要设计或评审的范围，利用已有资料；证据不足时给出带假设的方案，不要求先完成整套访谈。
「数字生命」是组织设计问题的类比，不代表传统软件没有迭代能力，也不保证系统具备自主演化能力。

## 三部分与责任

| 部分 | 负责 | 不应混入 |
|---|---|---|
| Seed | 价值目标、必要结构、约束、反馈依据及其变更权 | 未验证假设、当前 SOP 或工具选型被伪装成永久规则 |
| Harness | 控制循环 / 工作流、上下文、工具与环境适配、权限、状态与恢复 | 将接入成功当成理解正确，或把提示当成权限强制 |
| Memory | 有来源的事实、偏好与经验，以及可追溯的检索和更新 | 无来源结论直接变成群体策略或核心规则 |

Harness 统一表示运行时外壳，环境接入属于 adapters/tools 子部分，与 harness-design 使用同一含义。
三部分是设计视图；模型、评估、治理、成本和部署仍需在方案中有明确责任，不能由类比省略。
记忆积累、运行策略更新和模型权重训练是不同操作；本技能不隐含授权自动训练或发布。

## 设计流程

1. **定义服务结果与使用节奏**。区分一次性、低频和持续使用；确认受益者、付费方及其他受影响方。
2. **整理种子与边界**。经验判断、规范要求、目标、策略分别处理；写明底线、主要结果和次级目标的取舍。正式交接读取 [种子契约](../seed-extraction/references/seed-contract.md)。
3. **选择运行结构**。依据步骤确定性、实时观察、并发 / 恢复与隔离需求，选择工作流、单 Agent 循环、状态图或多智能体；复用现有平台能力。细节见 [Harness 设计](../harness-design/SKILL.md)。
4. **定义记忆读写与生效**。先决定谁的数据、何种内容、何种授权和作用范围，再选择存储；向量库只是选项。设计更新或学习时读取 [记忆生命周期](../retention-diagnosis-loop/references/memory-lifecycle.md)。
5. **设计结果评估与改进**。观察结果、用户感受、客观证据和副作用，按任务选择；把观察、因果假设、实验结果和发布决定分开。
6. **检查部署、成本与隐私取舍**。列出本地、服务端、模型供应商及第三方工具实际能看到的数据，明确未满足条件。

按依赖推进，不要求用户没有提出的外部部署、投放或实验。
相关技能未安装时继续给出本层方案和依赖缺口，不声称已完成其验证或取得生产批准。

## 环境接入与验收

对每项接入写明对象、权限、可读 / 可写能力、数据新鲜度、错误与恢复方式。
验收用有范围的真实任务或隔离试跑，记录成功率、误操作、人工介入、成本和未覆盖情形。
有限样本中未发生越权只能说明该样本的结果，权限边界还需配置检查和针对性测试。
接入能力与模型理解、输出质量分别评价；优先使用稳定接口，界面操作按实际需要采用。

## 隐私设计

敏感内容优先评估端侧处理；部署选择应同时满足用户要求、任务能力与成本约束，不能用「端侧优先」假定任何云端方案都不可用。
若选择「明文不出设备」作为硬要求，需验证推理调用、遥测、日志、崩溃报告、备份和第三方工具路径都符合。

- 加密、去标识化、向量化、聚合与差分隐私各自解决不同问题；脱敏特征仍可能可关联或可推断。
- 按服务器、供应商、备份和设备的实际可见字段定义威胁模型，注明信任前提与残余风险。
- 端到端加密需交代谁持有密钥、如何跨设备与恢复，以及服务端因此无法执行哪些分析；服务器持有解密密钥时不能宣称服务器不可见。
- 为失败回放定义快照位置、访问权、保留期与删除传播；强隐私模式下可使用端侧回放或不含原文的模拟样本，明确回放能力损失。

验收使用数据流核查和针对性测试，不承诺单靠「服务器只有公钥」就无法推断身份、时间或状态。

## 商业与改进

「用户价值 → 留存 → LTV → 可持续」是一种需要检验的业务假设，受需求频率、渠道、人群、价格和替代品影响。
一次性任务成功后不再使用可能符合预期；有些任务以成功率、节省时间、复发率或下次需求时回访率衡量。
收入、成本和用户价值可以同时作为目标；在底线内优化，不默认增长必然伤害价值。
CAC/LTV 阈值、回本期和获客安排是业务配置，不是通用种子，更不隐含投流授权。

## 输出与示例

输出包含：服务范围与目标取舍、种子引用与缺口、Harness 结构、记忆与更新边界、评估、数据流、成本假设和最小验证方案。

输入：「为客户做一次数据迁移，迁完后通常不会再打开助手。」
结果：以迁移准确性、完整性、时间和后续故障衡量价值；不为提高日活增加无关提醒。
任务状态用 Harness 保存，用户偏好与可复用迁移经验按不同生命周期处理，不把成功后离开直接写成流失失败。
