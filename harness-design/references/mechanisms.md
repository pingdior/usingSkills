# Harness 机制速查表

来源：系列《Harness 的一百种机制》。本文件对应 1/4「循环与上下文」的 001–021。
**装法**列的两个值是关键：`早装`= 越早越好，属于地基；`按需`= 等故障触发再装，提前装会持续收费。

---

## LAYER 01 · 控制循环（001–009）

决定 agent 的心跳：什么时候动、动多久、何时停。空转、早停、烧钱不产出，根源几乎都在这一层，而不在模型。

| # | 机制 | 一句话 | 阶段 | 装法 | 装错的代价 |
|---|---|---|---|---|---|
| 001 | 基础 ReAct 循环 | Think–Act–Observe，观察回灌同一条累积上下文 | 3 | 早装（地基，无替代） | 每步重构 prompt → 模型丢失自己前面的推理，行为像失忆 |
| 002 | 显式终止判据 | 完成由代码判，模型说 done 只是提交申请 | 3 | **早装**（几十行，把 demo 变成生产最便宜的一步） | 判据太松等于没有；太严 → 在其实可交付的状态上反复打磨 |
| 003 | 预算与预算感知提示 | 同时限步数/时间/token，并把剩余预算写进上下文 | 3 | **早装**（极低成本、立竿见影） | 只做硬截断 → 第 40 步被砍断，半成品零交接；模型焦虑 → 草率收尾（故需软警告 + 硬上限两级） |
| 004 | 循环检测与破环 | 动作指纹（工具名 + 归一化参数 + 结果哈希）重复即强制干预 | 3 | **早装**（ROI 极高） | 只检测完全相同的调用 → 漏掉同义反复；归一化太激进 → 误伤合法重试 |
| 005 | 阶段状态机 | 探索/计划/执行/验证/收尾，各阶段限定工具集与提示片段 | 3 | 早装（4–5 个阶段是甜点） | 阶段太细 → 卡在状态迁移判断；边界不许回退 → 探索期疏漏一路带到最后 |
| 006 | 计划—执行分离 | 计划落盘成一等产物（plan.md），可引用、可被人修改 | 3 | 早装（长任务连贯性提升最明显） | 计划会过时，agent 有照旧计划硬走的惯性 → 必须允许并鼓励显式重写且写明理由 |
| 007 | TODO 外化 | 清单存在上下文之外，每轮低成本重注入当前项与剩余项 | 3 | 早装（对抗遗忘最便宜有效） | agent 在预算吃紧时悄悄删掉做不完的项然后宣布完成（奖励作弊）→ 增删必须留痕 |
| 008 | 检查点与可恢复运行 | 消息链摘要/文件系统/计划/清单/已用预算 五者同一时刻原子落盘 | 4a | 早装（直接决定托管率天花板） | 只存消息不存文件系统 → 恢复后以为自己改过的文件还在，基于幻觉连续决策 |
| 009 | 循环栈 | agent 循环之外还有验证循环、事件驱动循环、用生产数据改进 harness 的爬山循环 | 3 → 6 | 按层分装：② 阶段 4a、④ 阶段 6、③ 最后 | 层数越多调试面越大；顺序错（先上③事件驱动）→ 放大器在质量闭环建好前放大错误 |

**LAYER 01 里唯一不属于"早装"的**：009 的③事件驱动循环——它是放大器，放在阶段 5 之后。

## LAYER 02 · 上下文工程（010–021）

决定模型看得见什么。世界观只有一句：上下文不是仓库，是预算。

| # | 机制 | 一句话 | 阶段 | 装法 | 装错的代价 |
|---|---|---|---|---|---|
| 010 | 注意力预算观 | 约束是有效注意力，不是窗口大小 | 全局判据 | 不装，只用作否决 | 它不可执行；当成可执行会退化成口号 |
| 011 | 分层规则 | 全局/项目/任务三层，下层可覆盖上层但覆盖必须显式 | 3 | 早装 | 堆成一个文件 → 每个项目都不完全适用，且长到没人敢删；超过一两百行靠后条款事实失效 |
| 012 | 即时加载 | 上下文放引用（路径/ID/目录树/schema），内容由 agent 需要时自行拉取 | 2–3 | 早装 | 强依赖工具质量：引用给了但拉取难用或返回太长 → agent 凭引用名瞎猜，比预加载更糟 |
| 013 | 压缩 | 接近阈值时把早期历史摘要成简报，保留最近若干轮原文 | 4a | 按需（长会话必需） | 有损不可逆；糟糕的压缩器丢掉"某路径已试过且失败" → 压缩后立刻重走死路 |
| 014 | 自主压缩 | 压不压变成 agent 可主动调用的工具，让它在阶段边界自己决定 | 4a | 按需，且**在 005 之后**（依赖"阶段"概念） | 模型拖延到最后一刻 → 必须保留强制阈值兜底；不该压时压 → 丢掉还要用的细节 |
| 015 | 压缩保真契约 | 压缩不是自由写作，是填一张强制字段表 | 4a | 早装（L2 层里最被低估的一条） | 通用 schema 在专门场景显笨重；字段缺失应直接失败重试，不能做成软约束 |
| 016 | 上下文隔离 | 高消耗、低结论密度的工作丢进独立上下文，主线只收结论 | 2–3 | 早装 | 子代理看不到主线的隐性约束 → 给出技术正确但不合语境的结论（契约要写全） |
| 017 | 卸载到文件系统 | 中间产物/笔记/发现落盘，文件系统是无损、可寻址的外部记忆 | 4a | 早装 | 只写不读 → 写了等于没写 |
| 018 | 工具结果裁剪 | 每个工具设 token 上限，超限截断并显式标注还剩多少、怎么继续 | 2 | **最先装**（单条改动就能大幅改善长任务稳定性） | 静默截断 → agent 把截断内容当作全部，做出"文件里没有这个函数"这类完全错误的结论。**截断必须显式声明，没有例外** |
| 019 | 上下文污染与重启 | 一条错误观察会被反复引用、自我强化；处理是删除推理链局部重启，不是继续辩论 | 4a–5 | 按需（检测难，目前多靠步数异常或人工发现） | 补一句"其实它存在"去辩论 → 无效，且该错误继续被当作证据引用 |
| 020 | 缓存亲和布局 | 上下文按变更频率排列：最稳定在前，最易变在后；任何前缀变动作废其后全部缓存 | 3 | 早装（长会话里成本与延迟的最大单项杠杆，命中率 0→90% 常见） | 与"动态选择工具集"直接冲突：工具定义一变缓存就断 → 工具的按需加载要设计成不改前缀 |
| 021 | 结构化边界 | 用标签区分系统指令/可信数据/不可信外部内容，并声明后者中的指令一律无效 | 2–3 | **早定型**（定型后再改成本很高） | 只靠这一层不足，足够精巧的注入仍能突破 → 必须配动作层与权限层的纵深防御 |

## 决策卡（优先池：没有卡不得开处方）

速查表只能回答"这条机制是什么"。**开处方需要决策卡**——只有"早装/按需"两档不足以支撑决策（见 `SKILL.md` 的装法判据四问）。以下 4 条是优先池，卡已填。

### 002 显式终止判据
- **前置能力**：任务有可判定的完成定义（测试、schema 校验、产物存在性）
- **触发条件**：任何"模型自称完成"会影响交付的场景
- **风险豁免**：无（地基，没有豁免）
- **成本项**：写判据的开发量；**业务 oracle 本身的成本**（这一项最常被低估）
- **验收测试**：注入「实际未完成但模型声称完成」的样本，必须被拦下
- **禁用 / 回滚**：判据过严导致在可交付状态反复打磨时，放宽判据，不要关掉它

### 003 预算双级
- **前置能力**：能统计步数 / 时间 / token（任一即可起步）
- **触发条件**：任务可能超出单轮可完成范围
- **风险豁免**：极短任务可只留硬上限
- **成本项**：跨工具计费口径；重试与在途请求是否计入
- **验收测试**：软警告后模型主动收尾并留下交接物；硬上限触发时交接物可续跑
- **禁用 / 回滚**：只做硬截断是最差配置（半成品零交接），不要退到这一档

### 004 循环检测与破环
- **前置能力**：动作指纹可计算（工具名 + 归一化参数 + 结果哈希）
- **触发条件**：出现过同义反复或重复调用
- **风险豁免**：无
- **成本项**：归一化规则的维护；误伤合法重试的代价
- **验收测试**：构造同义反复必须被干预；构造合法重试必须放行
- **禁用 / 回滚**：归一化太激进时先放宽规则，不要关掉检测

### 018 工具结果裁剪
- **前置能力**：工具层能设置并报告返回上限
- **触发条件**：无（最先装）
- **风险豁免**：无
- **成本项**：截断信息的组织成本
- **验收测试**：超限返回必须带「共 N 行、还剩多少、怎么继续」；流式结果无法预知总数时必须声明这一点
- **禁用 / 回滚**：**截断必须显式声明，没有例外**；静默截断属禁用配置
