# 种子提炼（Seed Extraction）

## 核心定义

种子 = 在明确业务边界内，关于"价值如何产生、业务如何成立、结果如何验证"的一组
**最小、相对稳定、可检验**的基本关系与约束。

种子是价值的**必要条件**（哪些关系一旦被破坏，价值必然崩掉），**不是充分条件**
（怎样把价值做出来）。充分路径留给后续演化。

## 四部件（每条种子必须写清）

- **价值指向**：为谁创造什么真实改变，什么结果算成功。
- **必要结构**：哪些参与者、对象、资源、责任关系支撑价值产生。
- **稳定约束**：无论采用什么策略，都必须满足哪些条件。
- **反馈依据**：通过什么证据判断成败、发现偏差并修正行动。

**粒度**：四部件是**文档级章节**；每条种子是稳定约束表里的**一行**，行内必须写全四要素（适用范围 → 必须满足的关系 → 支持证据 → 什么发现会迫使我们修改它）。两者不是同一层东西，不要混用。

## 三限定

- **最小**：每一项都必要——删掉它，系统会失去价值判断、业务约束或纠错能力。
- **稳定**：在约定的范围 × 时间尺度内，经得起组织、技术、流程变化的检验。**交付时必须显式写出"范围"和"时间尺度"两个维度**，否则"稳定"无法判断。
- **可检验**：能指出支持它的事实，也能说明什么反例会迫使我们修改它。

## 五步提炼法

1. **缩到"一次价值实现"**。别研究"物流行业"，先研究"一件货物从承诺送达到完成交付"。
   回答五问，得到行业基本结构（参与者/对象/状态/资源/责任/证据）：
   - 谁需要什么结果？谁付钱？
   - 过程中有什么对象发生变化？
   - 谁掌握信息、作出决定、承担后果？
   - 哪些资源有限，哪些承诺相互冲突？
   - 最后凭什么判断结果真的发生了？

2. **从具体案例挖隐含约束**。优先覆盖：正常完成、失败、退款纠纷、需资深人员处理的例外。
   追问："为什么必须这样处理？省掉这一步，具体会在哪里出问题？"
   直到答案落到可观察机制：**资源冲突 / 信息缺失 / 激励冲突 / 责任无人承担 / 结果无法验证**。
   答案停留在"行业一直这样做"= 还没挖到底。失败和纠纷暴露隐藏约束最快。

3. **用变化和反例筛选候选种子**。每条候选规则做三次检验：
   - 跨组织：换一家做法完全不同的公司，还成立吗？
   - 跨技术：人工换 AI、线下换线上，约束还存在吗？
   - 反例：能找到绕过它却仍持续创造价值的真实案例吗？
   同时追问因果：它稳定是因为物理条件、经济机制、认知特点，还是当前制度？

4. **把"行业道理"写成可检查的规则**。每条种子写清四件事：
   **适用范围 → 必须满足的关系 → 支持证据 → 什么发现会迫使我们修改它。**
   最后一项让"核心基因"保留修正能力。规则要能落到系统设计（可保存、可识别、可检查），
   而不是口号（"履约很重要"无法指导演化）。

5. **用新案例验证**。拿没参与提炼的案例检查：
   - 它能提前指出哪些失败风险？
   - 它能解释专家为什么这样决策？
   - 它有没有禁止一种实际可行的新做法？

## 质量标准

好种子 = **排除破坏价值的变化 + 容纳创造价值的变化**。只有限制没有容纳 = 系统僵化。

种子自检问题：**它能否让系统在持续尝试新做法时，仍守住价值成立的条件，并知道自己是否正在变好？**

## 关键纪律

- **按稳定性分层**（不同层不同修改成本）：物理约束 > 法律/合规 > 经济机制 > 认知/习惯。
- **三档分类**：核心约束（写进种子）、制度规则（可配置）、经营假设（待验证）。三档修改成本不同。
- **评价基因在闭环外**：价值指向与反馈依据是"评价基因"，由治理层修订，**不允许系统自动改**（防 Goodhart 漂移：系统会为了指标把"变好"偷换成"指标变好"）。
- **变更权要写进产物，且要落到权限层**：每条种子标注 `变更权`（`治理层` / `可配置` / `待验证`）。注意这只是**提示层**约束——真正的强制需要运行时拒绝写入种子与评价器，即把约束沉到判据层/物理层（见 harness-design 的三层下沉）。只写一句"不允许自动改"，等于没装。
