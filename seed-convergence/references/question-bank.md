# 种子收敛问题库

根据关键缺口选择问题；此文件不规定固定轮数或交付状态。正式状态与交接字段见 [种子契约](../../seed-extraction/references/seed-contract.md)。

## 先判断需要补什么

| 输入 | 需要区分 | 可选问法 |
|---|---|---|
| 「行业一直这样」 | 惯例、规范或已有验证的经验 | 来源是什么？是否有不同做法？各自结果如何？ |
| 「这是核心」 | 价值目标、必要约束或有用策略 | 它具体影响什么结果？在哪些条件下适用？ |
| 「我们一直写死」 | 必要限制与历史包袱 | 有哪些合法替代方案？放开后担心的具体风险是什么？ |
| 「我觉得可能」 | 假设及其证据缺口 | 支持它的线索是什么？什么信息会改变判断？ |
| 「客户要求的」 | 合同承诺、个别偏好或普遍需求 | 哪些客户、什么约定、到什么时候有效？ |
| 「老师傅凭经验」 | 隐性判据及其可靠范围 | 当时看到了什么？哪些情况下这套判断会失准？ |
| 没有提供具体记录 | 当前证据不可得，原因未定 | 可否提供脱敏材料、替代记录，或先标为待验证？ |
| 「收入、效率也是目标」 | 多目标与底线之间的关系 | 在不损害主要价值的前提下，可以优化哪些目标？冲突时如何取舍？ |

## 边界与价值

- 本次要支持哪个决策？服务从哪里开始，到哪里结束，或按什么周期观察？
- 谁使用、谁付费、还有谁承担后果？是否存在不同但都合理的目标？
- 用户实际得到什么改变？准确性、费用或时间是否直接构成价值？
- 哪些指标是结果、哪些是代理、哪些是不能突破的底线？
- 成功之后不再使用，是否恰好是预期结果？

## 结构与机制

- 哪些对象、资源和责任关系影响结果？已有证据在哪里？
- 省掉某步时观察到过什么？未观察到时，推断基于什么？
- 资源容量、信息不足、激励冲突、责任缺失、验证困难是否解释得通？还有别的解释吗？
- 原因是否来自物理过程、时间耦合、组织协调、认知限制或尚未识别的机制？无需硬塞入前五类。
- 关系是必然、概率性的，还是只在特定人群和条件下成立？
- 哪些冗余虽然不影响单次成功，却有助于异常恢复？

## 支持、反例与规范来源

- 有正常完成、失败和例外的对照吗？是否只记录了失败者或幸存者？
- 换组织、技术或时间范围后，关系还成立吗？
- 有没有绕过当前策略仍成功的合法案例？它反驳的是策略唯一性还是业务约束？
- 若是法律、合同或组织规则：原始来源是什么，谁有权修订，如何检查违反？
- 缺少资料是未记录、暂不可访问、保密限制，还是其他原因？原因未知时不下判断。

## 副作用与目标取舍

- 哪些人或情境可能不适用？已发现的副作用与尚未覆盖的范围分别是什么？
- 检查过但没发现反作用时，样本与条件是否足够？不能把「没有发现」写成「绝无风险」。
- 在质量不下降的前提下减少成本、改善收入，是否符合既定目标？
- 哪些底线不可用收入或增长交换？谁负责批准例外（若允许）？

## 反馈与 Goodhart 检查

- 什么记录能证明结果发生了？测量有多大延迟和误差？
- 指标改善而真实结果没有改善，有哪些可能解释？
- 如果只优化这个指标，会发生什么偏离？如何用其他结果或护栏识别？
- 指标间不一致时，哪些事实可继续确认，哪些动作应暂缓？

## 一个展开示例

用户：「必须当天响应，不然客户就走。」

1. 查是否存在当天响应的合同义务；有则保留为指定范围内的规范性约束。
2. 查延迟、客户损失和流失的实际记录；只有访谈时标为用户陈述，不宣布因果成立。
3. 比较紧急与非紧急任务、替代供应商及不同等待成本，寻找竞争解释。
4. 将「统一当天回复」和「按紧急程度分流」作为可比较策略。
5. 输出已支持关系、适用边界及缺口；无需为了结束访谈声称延迟必然导致流失。

## 收尾

用未参与提炼的案例检查误报、漏报和被错误禁止的合法方案。
用户保留案例、独立获得的真实案例和模型构造场景分别标注，记录来源与局限。
证据不足时交付草稿和下一步，不增加与主文件冲突的额外交付门槛。
