# Harness 设计（Harness Design）

## 第一原则

模型给上限，Harness 决定你离上限多远。（**修辞，不是判据**：上限本身、以及"工具能拿到的信息边界"都没有定义，无法据此做取舍。）

但**机制清单回答"零件有哪些"，阶段路径回答"何时该加"**。**经验假设（无样本总体与归因方法，未验证）**：多数 harness 问题不是缺机制，而是装错了时候：装早了是负债（每轮持续收费），装晚了是事故（烧钱不产出）。

所以本 skill 的输出永远是三件事：**现在装什么 / 现在千万别装什么 / 怎么算装好了**。

不要一上来就搬机制表。先定位阶段，再开处方。

## 主干：六阶段演进序

来自真实实践的顺序。用户描述现状时，先把他的话映射到这张表的某一行。

| 阶段 | 目标 | 退出判据（可提交的证据 + 要通过的测试） | 该装 |
|---|---|---|---|
| 1 拿到真实动作序列 | 拿到真实动作序列与卡点 | 有 ≥2 次真实运行的 trace（不是回忆），且覆盖至少 1 个异常分支 | 不装机制，只记录 |
| 2 搭建复用工具 | 重复动作变成可调用工具 | 工具接口 + 契约测试 + 超时/错误返回 + 副作用测试通过 | 018 返回体预算、012 返回引用、021 结构化边界、016 子代理=窗口隔离 |
| 3 形成框架 | 工具之间有约定与编排 | 新增一个代表性能力时不复制控制循环，且原回归集仍全绿 | 001 累积式 ReAct、005 阶段状态机、002 终止判据、003 预算双级、004 破环、011 分层规则、020 缓存布局、006/007 计划与清单外化 |
| 4a 自省闭环 | 能对自己的产出与轨迹打分 | 注入一个已知故障：能发现、定位、修复、复验，且不回归 | 008 检查点恢复、017 落盘+回读、013/014/015 压缩三件、019 污染处置、009② 验证循环 |
| 5 做真实项目 | **收集失败样本**（不是产出业务价值） | 至少一个真项目跑完（或标注清楚的影子试跑），失败样本含输入快照、可重放 | 实战检验 002/003/004/019；009③ 事件驱动**仍然不要开** |
| 6 重构 → 提高托管率 | 约束往下沉，人逐步退出 | 三个托管率分项在固定任务集上改善，且事故预算与质量门槛不恶化 | 011 做减法、015 补字段、020 重排、009④ 生产改进闭环 |

**不可跳过的是"真实动作序列"这个输入，不是"人肉走一遍"这个动作**：机制表不告诉你该自动化什么，只有真实 trace 能。已有等价 trace（历史日志、录屏、别处跑过的记录）可替代重新手工执行。**但口头回忆不算**——那会把输入精度降到和"听用户讲行业本质"同一水平。

**阶段 3 是地基而非优化**：002 终止判据、003 预算感知、004 破环在出处里被明确标为"几十行""极低成本""ROI 极高"。它们属于框架地基，不属于阶段 6 的提质项。

### 4a 与"生产改进"是两件事（最容易搞混的地方）

- **4a 自省闭环**（阶段 4）——真实项目**之前**就能建，而且必须建：对自己的产出按判据打分、对自身执行轨迹做破环/预算/污染检测。出处的排序是 ①→②→④→③，验证循环（②）明确排在事件驱动（③）之前。
- **生产改进闭环**（阶段 6，原编号 4b）——**只能**在真实项目之后：把生产 trace 喂给分析 agent，产出 harness 配置改动建议。没有真实数据，"harness 自我进化"是自嗨。

用户说"让 harness 能观察和改善自己"时，**先问清是哪一件**。此前把它编成"阶段 4b"，会让时机判断整体提前一个阶段。

## 三层下沉：托管率的度量与唯一抓手

任何约束最终只有三种存在形式，靠谁执行完全不同：

| 层 | 形式 | 例子 | 人的负担 |
|---|---|---|---|
| 提示层 | 写进规则文件，靠模型自觉 | "完成后请务必运行测试" | 高（还得检查它有没有照做） |
| 判据层 | 由代码判定，模型只能提交申请 | 测试全绿 + 改动在允许路径 + 无新增 lint | 中（判据对了就不用盯） |
| 物理层 | 错误动作根本不可用 | 探索阶段不挂载写工具 | 低（想错也错不了） |

**托管率 = 约束从上层搬到下层的进度。** 每设计一条约束都要问：它能沉到哪一层？沉不下去的，人就得永久参与——那就是托管率的天花板。

**托管率必须能算，且拆成三个分项，不要合成一个数**：

- **无人介入合格完成率** = 无需人介入且通过判据的任务数 ÷ 总任务数
- **人工分钟数** = 每任务人工介入时间的中位数
- **约束强制覆盖率** = 由判据层或物理层强制的约束条数 ÷ 全部约束条数

比较的前提是**固定任务集**，且**事故预算与质量门槛不恶化**。否则删掉一个审批环节就能让"介入点减少"，数字变好而系统变差。

## 否决判据：上下文是预算，不是仓库

新增任何机制前先过这一问：**它占掉多少有效注意力，换来多少确定性？**

- 30 个相关文件塞进 200K 窗口，正确率通常低于"目录树 + 3 个核心文件 + 按需拉取"。**这条可检验但尚未检验**（缺任务集、检索策略、模型与正确率口径），按假设用，不要当结论引。
- "有效注意力"没有直接度量，所以这条只有一个用法：**否决别的方案**，不可直接执行。把它当口号复述等于没说。**否决时必须写出被否决方案在"有效注意力"上的具体冲突**，写不出就不许引用本条——否则它就成了不可反驳的裁决。
- 推论：**装错的机制会持续收费**——缓存前缀失效、规则文件超长、阶段过细，都是每一轮都在付费的债。

## 反模式清单（装错时候的代价）

| 反模式 | 症状 | 正确做法 |
|---|---|---|
| 让模型自称完成 | 没跑测试就说"已修复" | 002 终止判据，由代码判 |
| 静默截断工具返回 | 断言"文件里没有这个函数" | 018 显式声明"共 N 行、还剩多少、怎么继续" |
| 只存消息不存文件系统 | 恢复后基于幻觉连续决策 | 008 五者同一时刻原子快照 |
| 动态内容进提示前缀 | 时间戳放系统提示第一行 → 缓存全废、成本翻数倍且无人察觉 | 020 时间戳放最后一条用户消息 |
| 规则文件超长 | 超过一两百行后，靠后条款事实失效 | 011 持续做减法，删掉已被工具/校验强制的条款 |
| 阶段划太细 | 卡在状态迁移的判断上，开销反而上升 | 005 保持 4–5 个阶段，且允许回退 |
| 落盘但不回读 | findings.md 写了等于没写 | 017 显式提示读回 |
| 清单可被 agent 自删 | 预算吃紧时删掉做不完的项，然后宣布完成（奖励作弊） | 007 增删必须留痕 |
| 质量闭环未建先上事件驱动 | 放大器在不该放大的时候放大错误 | 009 顺序 ①→②→④→③ |
| 压缩丢反事实信息 | 压缩后立刻重走死路，白烧一段预算 | 015 强制字段，尤其"已排除的路径 + 排除理由" |
| 试图"说服"模型改信念 | 错误观察被反复引用、自我强化 | 019 保留任务与已验证事实，丢弃推理链，局部重启 |
| 子代理当角色扮演 | 它不知道主线的隐性约束，给出技术正确但不合语境的结论 | 016 契约写全；它的价值是窗口隔离 |

## 装法判据（"早装 / 按需"两档不够用）

`references/mechanisms.md` 只给了"早装 / 按需"两档，**不足以支撑决策**。开处方前四问都要有答案：

1. **能力依赖**：前置能力就绪了吗？（没有压缩器就不必启用压缩运行时逻辑，但契约可以先定义）
2. **风险先验**：它拦的是高损失动作吗？高损失动作（支付、通知、写外部系统）**不以"已经出过故障"为安装条件**。
3. **边际成本**：开发、维护、token、延迟、误拦截分别是多少？"持续收费"是四笔不同的账。
4. **反事实收益**：装与不装的成功率、事故损失、人工时间各是多少？

缺任一问的答案，不得开处方。**风险门禁优先于收益排序。**

## 执行流程

1. **定位阶段**。问这几个问题，别问"你用了什么框架"：
   - 现在还有哪一步是你手工做的？做过几遍了？
   - 你有一份编排，还是一堆脚本？新增能力时改哪里？
   - 有失败样本吗？上次跑崩/空转是什么时候，原因写下来了吗？
   - 现在谁在盯着它跑？（人必须盯着的环节 = 托管率天花板）
2. **一次只上 1–3 条机制**，按 ROI 排序。优先池：002 终止判据、003 预算双级、004 破环、018 显式截断（具体做法与决策卡见 `references/mechanisms.md`，不要在判据层复述实现细节）。
3. **每条机制写验收**：怎么算装好了？尽量写成可自动判定的形式——这一步本身就是在建判据层。
4. **标注下沉路径**：这条约束最终能不能沉到物理层？不能的，明确写出"此处需要人"。
5. **留回填槽**：真实项目每挂一次，回来更新机制表与验收标准。**失败样本是主要更新来源**——此前写成"唯一"，等于排除了成功对照、安全预防、模型/价格变化这四类合法来源，没有给出排除理由。

## 输出格式（回答长这样）

- **你现在在第 N 阶段**：一句话依据。
- **现在装**：1–3 条机制 + 具体做法 + 验收判据。
- **现在别装**：列出这个阶段装会亏的机制 + 亏在哪。
- **下沉路径**：每条约束的层级迁移计划（提示 → 判据 → 物理）。
- **缺口**：这条路径上你没有的东西（判据表？恢复能力？成本结构？）——成本结构与判据表要在阶段 3 就定型，它们不是阶段 6 的优化项。
