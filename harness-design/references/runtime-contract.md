# 运行契约

在设计有状态任务、工具写入、并发、等待与恢复时读取。简单只读任务只采用与其风险相关的部分。
本文件维护运行状态与副作用恢复规则；机制表引用它，不另建状态机。

## 任务与节点

任务记录 task_id / run_id、目标与允许范围、种子和策略版本、预算、已用资源、产物引用及验收结果。
图节点声明输入输出、读写哪些状态、谁能修改、条件边与失败出口。
并行节点需明确独立性、汇总等待条件、重复结果去重、共享状态冲突处理；子任务取消不自动撤销其已生效动作。

任务依赖 DAG 使用同一份当前有效边集做就绪和优先级计算；失败、取消或进程退出不代表前置成果验收成功。
依赖增删有授权、版本与来源，不能通过撤边绕过强制要求；有环计划应被拒绝，执行状态图中的有界循环另行处理。
派发候选先满足依赖与状态，再接受资源、授权、冲突和持久停派检查。最长链启发式、准入预测与公平性见 [长期运行机制](long-running-runtime.md)。

## 可观察状态

| 状态 | 含义 | 后续 |
|---|---|---|
| running | 在允许范围内执行 | 继续或进入以下状态 |
| waiting | 等待外部变化或用户输入 | 记录等待对象、续跑条件、截止时间与已用预算 |
| succeeded | 结果满足本次验收与范围 | 交付，并保留验收证据 |
| partial | 已有部分结果，仍有明确缺口 | 如实交付，续跑时保留缺口 |
| failed | 当前尝试失败 | 给原因、可恢复性与下一步 |
| budget_exhausted | 达到资源或时限边界 | 停止新增动作，交付已持久化的状态 |
| cancelled | 用户或治理方取消 | 取消可取消动作，核对已发出动作的实际结果 |

重试是新的执行尝试，但累计预算和历史副作用不能被清零。waiting 不等于 failed。
任务成功需要产物检查；工具请求「已接受」不能冒充业务动作「已生效」。

## 派发资格与恢复预算

执行状态与派发资格分别保存：任务 failed 或 partial 不表示允许无限再次派发。
按稳定 task_id / trigger_id 和恢复路径记录 retry_count、retry_limit、stopped、stop_reason、stopped_at、resume_evidence_ref。
首次正常启动不计入失败后的重派次数；次数限额不代替总预算，也不能通过更换 run_id 清零。

- 认领一次重派与计数更新应在宿主的一致性边界内完成，避免并发扫描各自放行；记录尝试标识以核对启动前后崩溃的不确定状态。
- 达限后持久停派，重复扫描不得重复启动或持续新建同一耗尽告警。
- 恢复需有范围内的授权和条件变化证据，例如权限补齐、输入更新或故障修复；保留历史计数，新恢复周期仍受总体预算限制。
- 确定的权限缺失或无效输入可直接暂停该路径，无需为了凑次数重复执行。临时故障可按策略采用退避与有限重试。
- 退避控制频率，次数预算控制重复机会，幂等控制重复副作用；三者分别验证。

## 执行权与受保护写入

只有存在共享写入与接管时才需要该层；简单单执行者任务不强制实现分布式租约。
为资源或分区定义 owner_id、单调 generation、lease_expires_at，以及这些字段的权威存储与时钟来源。
接管以当前世代和租约条件做原子比较更新；写入端在其事务 / 原子边界内核验持有者、世代与期限，不能先在客户端查一次再无条件写入。

旧执行者可能仍在计算。新世代生效后，受保护写入入口应拒绝过期资格；校验使用当前权威值，不能只接受请求自己声明的更大数字。
正在并发提交的事务按底层数据库语义验证。已提交动作、无 fencing 检查的外部 API、独立文件写入不自动受到保护。
幂等避免同一逻辑动作重复生效，世代隔离阻止无效执行权提交；两者共同适用时需同时满足。
租约期限、续租、拒绝事件记录与人工接管按实际延迟和故障模型配置，不采用通用三秒租约假设。

## 工具契约

按需记录：工具名和版本、输入输出 schema、对象范围、所需权限、超时、费用、错误类型、完整性标识与副作用类别。

| 类别 | 示例 | 重试与恢复 |
|---|---|---|
| 只读 | 查询订单状态 | 允许契约内的有限重试，注意数据新鲜度与读取费用 |
| 支持幂等的写入 | 接受 idempotency key 的创建接口 | 同一逻辑操作使用同一键，核对幂等范围与有效期 |
| 不支持幂等的写入 | 某些界面操作、发送消息 | 使用目标记录或回执核对；无法核对时保留 unknown，不盲目重试 |

同一键对应的请求内容必须一致。使用新的键不是安全重试；用相同键发送不同内容也可能导致拒绝或错误复用。
幂等并不能替代授权，读取工具也可能带来隐私或计费风险。

## 写入账本与恢复顺序

对有副作用的操作，持久记录 operation_id、任务引用、目标、请求摘要、幂等键（若支持）、执行状态和结果引用。
敏感参数按隐私政策处理，不把密钥或原始用户内容默认写入日志。

1. 在执行前保存必要的操作意图和标识，避免重启后无法识别此前动作。
2. 发送请求；分别记录确认成功、确认失败与 unknown（超时、断连或回执丢失）。
3. 恢复时读取最新任务状态、产物版本和操作账本，重新校验权限、外部状态、预算与幂等有效期。
4. 对 unknown 先查询目标系统或可靠回执；确认已成功则复用结果，确认未生效且允许重试才重试。
5. 无法确认且重复有损失时，停止该操作并交接。需要补偿时使用有授权的补偿流程，不假定回滚检查点能撤回外部动作。

本地检查点保存受控状态的一致版本，以及文件 / 对象的版本引用或内容哈希。是否需要文件快照取决于任务，不强制对任意文件系统做原子快照。
外部系统、已发送消息和已结算交易不包含在本地原子边界内。采用至少一次执行时，要靠业务幂等和核对控制重复影响，不承诺通用恰好一次。
有接管和持久停派的运行还需核对当前执行权与派发资格；新会话不继承过期资格，也不绕过耗尽记录。

## 完成、验证与重启

- 结构检查、业务判据和开放性质量分别记录，不能将 schema 合法当成业务正确。
- 评估器应保留版本、已知误判与适用范围；模型评估不能自动修改自己的通过门槛。
- 压缩或局部重启需保留授权、目标、可信来源、排除路径及理由、剩余任务、预算和副作用引用。
- 工具或规则版本变化时重新核对兼容性；不为续跑或缓存复用过期权限。
- 能由宿主持续保存的交接状态不依赖最后一次模型调用；硬截止可能没有收尾时间。
- 交接工作集保存原文 / 投影 / 缺失、选择范围、来源版本与预算回退；完整性与搜索覆盖分开核验。

## 最小故障验证

在隔离模拟器中测试：写入成功后回执丢失、确认未写入、幂等键失效、权限被撤回、合法轮询、预算结束和取消时已有在途动作。
长期运行增加：旧世代迟到写入、并发认领、重启后停派仍有效、依赖撤销与失败前置、必读材料缺失、已解决告警复发。
验收行为及外部状态，不只检查日志中是否出现「幂等」或「恢复」等词。
