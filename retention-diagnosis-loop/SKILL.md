# 留存诊断与自我迭代闭环（Retention Diagnosis Loop）

## 核心纪律

留存是"报警器 + 验收表"，**不是方向盘**。目标函数永远是"修复价值交付"，不是"拉高留存"。
直接优化留存 = 数据倒灌污染（加诱导、加社交上瘾 → 空心增长）。

## 因果链（单向，不能倒灌）

真实用户价值 → 留存 → LTV → 商业可持续

## 三角验证（真实用户价值判定）

**通用结构（任何领域都适用）**：判定必须同时看三层，缺一层就不能下结论。

- **证据层**：可测量的过程量。是证据，不是价值本身。
- **结果层**：用户行为发生了什么改变。
- **价值层**：用户主观上是否真的更好。

最低判据：**价值层 + 结果层改善，证据层作佐证**，且在连续两次测量间隔内成立。
分歧处理：证据层变好但价值/结果层没变，**是待检验假设，不是结论**——既可能是指标与价值脱钩（Goodhart），也可能是测量间隔太短或样本噪声。处理方式是**上报治理层，禁止自动修正**，并把它当成一个待验证假设去查。
失败信号（最高优先）：流失、指标长期无改善、伤害信号上升。

### 领域配置（示例：电商复购）

> **换领域时整体替换本节，其余各节不依赖它。** 本节的作用是示范"三层各自该填什么"，不是标准答案。

- 证据层：商品页停留时长、加购率、尺码表查看率
- 结果层：复购间隔、主动搜索品牌词的次数、客服工单中"问题已解决"的占比
- 价值层：用户自评"这东西帮我解决问题了吗"、NPS、退货理由分布
- 事件名：`view_item`、`add_to_cart`、`order_paid`、`order_refunded`、`support_ticket`、`nps_submit`

**注意**：价值层若使用第三方量表或标准化问卷，多数有版权，商用前需确认授权或换可商用等价工具。

## 双飞轮

- 价值飞轮：价值交付 → 数据 → 反馈 → 看见变化 → 留存。
- 经营飞轮：价值 → 留存 → LTV → 投流获客 → 更多数据。
- 咬合点 = 留存 / 付费。两层靠统一 `user_id + date` join，不互相直接调用。

## 留存差时的自我调整（六步）

1. **经营层报警**：留存跌破健康线（见下）。
2. **先排除获客与数据口径问题**：按渠道 × cohort 分层。某渠道整体差**通常是**获客问题（**待检验**，也可能是渠道人群与产品不匹配），调素材前先确认不是埋点/归因口径发生了变化。
3. **三角验证定位断裂点**：画流失漏斗找最大台阶，并与三层指标对照。漏斗步骤由领域配置给出（电商示例：激活→首次下单→第 2 单→首次复购→N 次）。
4. **生成可证伪假设 + 子集实验**：例"首次下单前要求填的信息太多" → 5% 流量 A/B 测精简表单 vs 完整表单，≥7 天。
   **开跑前必须写明**：最小样本量、主要指标、效应门槛、停止规则、伤害护栏。**伤害护栏触发即刻停止实验，优先于统计显著性。**
5. **写回 Memory**：群体级（策略/渠道/素材效果 + 效应量 + 样本量）与用户级（偏好/教训），失败也写。**写入默认只产生候选，不直接生效**，字段与发布条件见"共同账本"。
6. **种子层只上报**：定位到"价值指向错"或"反馈依据失效" → 治理层重提炼，禁止自动改。

## 边界

- 自动调整只在**策略层 + 环境接入层**（任务时长、提醒时机、话术、模板、渠道、素材、产品形态）。这里的 Harness 指 digital-life-service-design 的"挂载/环境接入"，**不是** harness-design 的 Agent 运行时外壳——**预算、终止判据、工具权限、恢复配置不在可自动调整范围内**，别被同一个词带跑。
- 种子层（价值指向/必要结构/稳定约束/反馈依据）**只上报、不自动改**。这只是提示层约束，真正的强制见"安全事件与护栏"与共同账本的发布条件。
- 安全事件与护栏触发优先于一切优化动作，处置协议见下节。

## 埋点字段（两层同源，统一 `user_id + ts + channel + cohort_week` join）

- 经营层：`attribution_install`、`activation`、`register`、`session_start`、`pay`、`unsubscribe`。
- 产品层：**事件名由「领域配置」一节给出**（通用要求是：每个事件带唯一 `event_id`；重试与补发按 `event_id` 去重）。此处不重复列举，避免两处漂移。
- **隐私红线**：只上报时长/次数/脱敏向量/端侧算好的指标值，**不上传明文内容**（原始语音/文本/视频不出设备）。
- **但"不上传明文"不等于"不可还原"**：`user_id + ts + channel + cohort_week` 再叠加价值层结果与安全事件，即使全程无文本，也足以还原"谁在何时处于什么状态"。**威胁模型必须按服务器实际可见字段逐字段写**，并逐个回答：这个字段进了服务器之后，能否与其他字段 join 出身份或状态？能，就必须改为端侧聚合 / 加密 / 加噪后再上报，而不是靠"没有明文"自我安慰。

核心表（示例命名，可替换）：`user_day_fact`（user_id + date 主键，价值/经营字段同表 join）、`group_memory`、`user_memory`、`diagnosis_run`、`experiment`。

## 安全事件与护栏（优先于一切优化）

**什么算安全事件由「领域配置」定义**（不同领域定义不同，如资金 / 账号 / 隐私 / 人身安全），护栏事件同理。安全事件或护栏事件触发时，**任何优化动作（含进行中的实验）立即暂停**，并按领域配置的协议处理。协议必须写明：

- 谁接收、响应时限是多少
- 是否人工介入、转给谁
- 哪些自动策略必须停用、什么条件下恢复
- 事后是否复盘进共同账本

**没有写完这套协议之前，不得开启任何自动实验。** 检测到安全事件却无处可送，比不检测更糟——它把责任留在了系统里。

## 数据口径（先定口径，再看数字）

数字的波动经常来自口径而不是价值。以下口径**一旦确定不得中途更换**：

- **事件 ID**：每个事件带唯一 `event_id`；重试与补发按 `event_id` 去重，不重复计数。
- **时区**：全局固定一个时区（默认 UTC 或业务主时区），跨时区用户按同一时区归日。
- **留存分母**：分母 = 该 cohort 周首次激活的去重用户数；分子 = 在 D_n 当天有合格会话的去重用户数。
- **成熟窗口**：D30 必须等 cohort 满 30 天后再看；未成熟 cohort 不进健康线。
- **归因窗口**：安装归因窗口固定并写进配置；超窗转化不计入该渠道。
- **最小样本**：分渠道 × 分 cohort 样本量低于阈值时**只记录、不出结论**。

## 共同账本（Memory / 失败样本 / 策略发布共用一套 ID）

`user_memory`、`group_memory`、失败样本、策略版本共用同一组键：

`memory_id、scope（tenant/user）、source_trace、seed_version、policy_version、evidence、confidence、valid_until、status`

**纪律**：

- 经验写入默认 `status=candidate`：**只产生候选，不直接生效**。
- 候选要变成生效策略，必须依次经过：离线回放 → 子集实验 → 批准。**没有审批不得发布。**
- 支持撤销与失效传播：种子升级、证据撤销、用户删除后，相关记忆与派生策略必须停用或重审。
- 失败样本必须带**输入快照 + 判定版本**，否则无法重放，也证明不了某次改动真的修好了它。

## 留存健康线

分层定线（激活周 × 渠道）+ 分位数 + 控制图：

- **黄**：D7 留存跌破同期基线 P25，连续 2 天。
- **红**：跌破 P10，或 7 天滚动均值破 3σ 下界。
- **不同天数不同入口**：D1 查 onboarding/首次价值；D7 查习惯回路；D30 查价值持续成立。
- 初始量级仅作合理性校验（D1≈30-40%、D7≈15-25%、D30≈8-15%），**必须用真实基线替换**。
- 先跑 2-4 周基线，再启用 P25/3σ 健康线。
