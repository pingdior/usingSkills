# 长期运行机制：选择、交接与恢复

在跨会话交接、持续任务队列、共享配额或执行者接管时读取。主文件负责架构选择，[运行契约](runtime-contract.md) 维护状态和写入规则，本文件提供适用条件、选择方法与验收场景。

## 来源与证据边界

参考 ToWow [Harness 运行机制专题](https://towow.net/articles/topics/harness-runtime-mechanisms) 的八篇文章，发表于 2026-09-15，查阅于 2026-09-17。
本次阅读的是实现解读及作者对已有测试的说明；没有直接核对 HSM 底层仓库的提交，也没有重跑数据库测试或生产工作负载。
每条机制的三个证据维度以 [机制证据记录](mechanism-evidence.json) 为维护来源：

- **source_behavior**：设计建议，或文章转述的实现行为；转述不是直接源码复核。
- **existing_tests**：未定位到测试，或文章说明了已有覆盖；规格、阅读测试说明和亲自运行测试不能混写。
- **runtime_benefit**：当前均为 unmeasured，记录收益假设及需要观察的结果。

原文已有边界需要一起保留：配额规划默认影子模式且自动迁移关闭；世代隔离只覆盖相应存储写入路径；访谈判停尚缺人工一致性与实际效果对照。
本文的工程建议可能比原实现更保守或更通用，应标为建议，不能倒写成原代码已经具备的能力。

## 按场景选最小组合

| 场景 | 需要检查 | 不必默认引入 |
|---|---|---|
| 单任务短时只读 | 完成、工具错误、宿主预算 | 配额预测、分布式租约或告警中心 |
| 跨上下文交接与长期恢复 | 026 工作集、008 恢复、027 有界重派 | 单靠角色名称拆出多个 Agent |
| 多任务持续调度 | 005 就绪与优先级、023 共享准入 | 不受任务类型影响的统一并发数 |
| 共享写入及接管 | 024 写入隔离、008 副作用核对 | 用租约过期证明旧进程已死亡 |
| 事件和巡检规模增长 | 022 索引、025 告警生命周期 | 已有数据库能力之外再造一套索引 |

## 026 上下文工作集

参考 [上下文工作集](https://towow.net/articles/harness-context-workset)。优先增强执行、修复与审阅之间的交接。

关键材料清单至少说明来源与版本 / 哈希、选择范围、生产者、必读理由、交付方式、覆盖状态及继续读取入口。
角色可以决定必读类别，但材料是否必读也取决于已知反例、验收条件和当前动作，不完全服从调用者的排序。
执行者需要目标、约束与前置成果；修复者还需要问题与复现证据；审阅者需要被审版本、实际改动、判据与机器观察。

- 原文完整是指**选定来源范围**完整，不要求每次传整个仓库。
- 原文、审计投影、尚未交付和来源缺失分别记录。投影只在明确阅读策略允许且保留范围限制时使用，不能把任意摘要当原文。
- 同文不同来源或生产者仍是不同证据身份；机器报告「通过」不能改标为独立审阅结论。
- 已交付全部必读材料、上游搜索充分、模型理解正确是三个不同问题。未搜索、未找到和确认不存在也不能互换。
- 重开工作集时按固定来源版本重取所选内容并核对；版本不可取得或发生变化时报告失配，不让带真引用的替换文字冒充原文。

预算应区分渲染文本的 UTF-8 字节数、模型 token / 上下文容量和获准费用。原文按字节控制材料选择，这些单位不能直接等同。
选定模式允许时，完整必读原文可触发**工作集软预算**回退，并明确超额；模型硬容量、权限和费用上限仍不可突破。
超过硬边界时分批取读、缩小当前动作或交接；必需来源丢失时停止依赖它的判断，而非无条件冻结所有工作。

验收：长验收条件不被静默截断；排序靠后的已知反例仍进入必读；摘要不能冒充原文；来源变更可检测；硬容量不足时不伪报完整。

## 027 有界重派与 024 写入隔离

参考 [有界重派](https://towow.net/articles/harness-bounded-redispatch) 与 [世代号写入隔离](https://towow.net/articles/harness-generation-fencing)。
持久预算、停派字段与执行权核验按运行契约实现，不在此定义第二套状态。

区分动作重试、失败后重新启动任务、执行权接管：幂等控制同一操作重复，重派预算限制新尝试机会，世代隔离控制谁还有资格写入。
重派耗尽后，后续扫描不能因「任务未完成」继续开新会话；恢复应改变失败条件并保留依据。更换模型不能补出缺失权限。
接管允许新执行者开始，并不停止旧执行者；受保护写入端的核验要覆盖真实原子边界。客户端预检或仅更新任务表不足以隔离迟到请求。
外部 API 未参与世代检查时，需另行处理其幂等、核对、串行化或补偿，不能宣传获得了完整接管保障。

原文默认三次自愈重派、三秒租约是项目配置，不直接复制为推荐值。
验收：达到上限后多次扫描及进程重启均不再派发；首次启动不误计为重派；旧持有者迟到请求被拒；并发接管只产生有效资格；不支持隔离的外部路径明确暴露。

## 005 依赖就绪与调度优先级

参考 [DAG 任务调度](https://towow.net/articles/harness-dag-dispatch)。
先用当前有效依赖边和经过验证的前置成果计算就绪集合，再应用配额、工具权限、模型容量与写入冲突限制。
节点失败不能释放成功依赖；授权撤边应同时影响就绪集合与优先级。计划 DAG 中的环应单独拒绝，递归防卡死不等于有环调度正确。

缺少可靠耗时估计时，可以尝试按后续最长链优先，但明确单位是**节点数量**。原文 makespan 字段不代表真实分钟数，也不证明最优排程。
相同输入采用稳定的平局处理；加入等待时间、截止时间或资源分类避免饥饿。耗时加权需要另行校准，不把单位链长结果直接当加权关键路径。
等长路径很多时限制枚举与说明输出，避免调度解释本身膨胀。

验收：失败前置仍阻塞；有效撤边可解锁；环被拒绝；长链优先不能绕过资源；紧急或长等待任务不会被无限延后。

## 023 配额预测与新任务准入

参考 [预测配额调度](https://towow.net/articles/harness-quota-admission)。
任务预算之外，再看共享短 / 长窗口的使用量、重置时间、观测新鲜度、消耗速度及在途清单。已有平台提供时直接复用。
可以保守组合近期速率、token 换算和窗口平均值，但须记录换算误差和新任务负载差异；未来任务更重时平均速率会低估需求。

- 先影子运行，记录建议与实际差异，再按授权与验证结果决定是否启用准入控制。
- 新鲜度或在途数据不足时不凭旧读数新增消耗该共享配额的任务；仍可按既定预算完成在途工作或推进不依赖该配额的工作。
- drain 表示收紧新入口，不直接终止在途会话。收尾、取消与迁移分别遵循权限和恢复契约。
- 预留空间要考虑在途工作、必要收尾及恢复消耗；长期窗口不能被短期余额覆盖。
- 对预测过度保守造成的闲置与排队也设观察，避免只优化用量曲线。

原文 90% / 95%、十五分钟提前量、300 秒新鲜度和 EWMA 权重 0.35 都是实现参数，未经校准不作为宿主默认值。
验收：短窗口有余量但长期不足时不误放行；过期观测不扩并发；降准入不误杀在途任务；记录预测偏差、意外中断、有效完成量及等待时间。

## 022 增量事件索引

参考 [增量事件索引](https://towow.net/articles/harness-event-index)。先测查询与反复解码开销，再决定是否需要独立索引。
事件账本是事实来源，索引是可重建的派生物；新增索引与完整重建使用相同的事件归属语义。
只追加已提交、按约定顺序且未索引的事件，记录游标 / 日志世代；重复输入、恢复或截断必须可检测并触发核对或重建。
按任务等入口先定位，再展开正文；冷启动与全量查询仍有成本，不宣称惰性加载消除了扫描。
原实现有单线程使用假设；多执行者共享可变索引要另设锁、事务或快照语义，不能从「有增量追加」推导出并发安全。

验收：增量与重建查询结果相符；重复追加不导致用户可见重复；日志截断不沿用旧偏移；并发模型明确；计量真实查询负担而非教学例子的倍数。

## 025 机器告警生命周期

参考 [机器告警去重](https://towow.net/articles/harness-alert-dedup)。围绕当前未解决问题归并，而非只比较上一条文本。
键应考虑租户 / 资源、可信来源、故障类型和必要原因；不机械抹掉对故障含义重要的数字。指纹用于归类，不提供真实性或安全证明。
归并后保存复发次数、首末时间和证据引用；样本或计数不能冒充完整事件历史。
已解决后再发生应重新提出或明确重开；原因不同、严重度升级和独立的人类求助不能被吞掉。
不把机器名前缀当认证。人的决策请求与机器巡检使用不同的归并策略，避免相同文字掩盖不同责任。

原实现对开集读取失败和生命周期读取失败有不同回退，后者仍可能归并。这里建议：关键告警无法确认生命周期时，优先新建 / 升级而非静默压制，并记录降级。
原文十四天窗口、四十字符规范化和短摘要长度均是项目策略，不直接推广。
验收：A/B/A 交替可正确归并；解决后复发有新入口；不同原因与严重度不丢失；生命周期不可读时明确降级；具名独立求助保留。

## 访谈就绪的衔接

专题第八篇 [访谈停止判定](https://towow.net/articles/harness-interview-stop) 属于进入下一步前的信息判断，规则维护在 [种子收敛问题库](../../seed-convergence/references/question-bank.md)。
其 readiness 与任务运行状态、种子批准状态分开。不能因为尚无部署批准，就自动阻塞隔离设计；也不能用信息分数代替必要授权。

## 验证方式

把上述验收转换为 [设计响应场景](../../evals/agent-design/cases.json)，并在实施对应运行机制时另建隔离执行测试。
本仓库检查器验证引用、编号、证据字段及场景规格，不运行 HSM、数据库故障注入或模型对照；报告中必须保持这个边界。
