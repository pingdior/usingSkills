# 种子契约（seed/v2）

本文件是这组技能中**种子交接字段、文档状态及其转换条件**的唯一维护来源。
状态描述交付物在指定范围内的可用性，不证明行业规律已被普遍验证，也不代替系统权限。

## 最小交接字段

允许 Markdown 或结构化对象；接入代码前再按宿主要求序列化，无需为访谈强制生成 JSON。

| 字段 | 含义 |
|---|---|
| schema_version | 固定为 seed/v2，与业务版本分开 |
| seed_id / version | 稳定标识与业务修订版本；没有既有标识时明确为本次新建 |
| status | 下表中的文档状态 |
| scope / time_horizon | 服务边界、适用人群 / 系统、时间尺度；持续服务注明观察周期 |
| value / structure / constraints / feedback | 四部件，具体内容见下方模板 |
| evidence / hypotheses / strategies / gaps | 来源索引、待验证假设、可演化策略、当前缺口 |
| governance | 责任方、允许的变更范围、批准证据引用；尚未指定或取得时写未知 |

每条约束至少有稳定 id、类型、适用范围、关系或要求、依据、检查方式、变更权。
适用时间与文档一致时可以继承；存在例外时单独注明。检查结果应关联约束 ID 和判据版本。

## 文档状态

| 状态 | 进入条件 | 可以做什么 |
|---|---|---|
| draft | 允许证据、边界或检查不完整，但缺口明确 | 讨论、补证据、隔离环境中的设计与试验；不得当作已批准生产规则 |
| validated | 四部件与类型完整；适配条目类型的依据及检查已完成；经未参与提炼的案例检查；关键缺口关闭或移出拟生效范围，局限仍有记录 | 提交治理决策；不自动获得生产修改权限 |
| approved | 在 validated 基础上，有责任方在有效权限内对该版本、范围和用途的批准记录 | 在批准范围内供 Harness / Memory 使用，实际发布仍遵循宿主权限与部署流程 |
| deprecated | 被替代、撤销或不再适用，记录原因及替代版本（若有） | 保留审计引用；不得继续作为生效依据 |

通常路径是 draft → validated → approved → deprecated。未通过检查仍交付 draft，不要求先满足全部验收才能交付草稿。
新证据引发实质性变更时创建新版本，从 draft 重新检查；旧版本是否立即停用按影响范围和风险决定，并记录传播结果。
只有文案调整且不改变语义时，按责任方既定版本政策处理，不制造重复审批。
批准不等于发布，分析 Agent 不得把自检通过冒充治理批准；既有授权覆盖本次动作时无需重复索取。

## 条目证据状态独立于文档状态

每条经验判断标为 unknown、hypothesis、supported 或 disputed，并记录来源及限制。
supported 表示在现有范围与证据下得到支持，不是普遍真理。规范性条目记录来源有效性和适用检查，不伪装成实验结论。
目标记录责任方与取舍声明；策略记录验证范围。未验证的策略和假设可以作为附件存在，但不得混入拟批准的强制约束。

## 建议模板

~~~markdown
# <服务> 种子 <业务版本>
schema_version: seed/v2
seed_id: <id> | status: draft

## 0. 范围与时间尺度
一次价值实现或观察周期：…
受益者 / 付费方 / 其他受影响方：…

## 1. 价值指向
主要结果：…
次级优化目标：…
不可交易的底线：…
冲突时的优先级或允许范围：…

## 2. 必要结构
参与者 / 对象 / 状态 / 资源 / 责任 / 证据：…

## 3. 约束
| id | 类型 | 范围与要求 | 来源及证据状态 | 检查方式 / 变更触发 | 变更权 |
|---|---|---|---|---|---|

## 4. 反馈依据
直接结果 / 代理指标 / 约束指标：…
成功、失败与副作用证据：…
测量局限、判据版本及责任方：…

## 5. 假设与策略（不作为已批准约束）
…
## 6. 缺口与验证记录
缺口、影响、下一步；保留案例与构造场景分别注明：…
## 7. 治理与交接
责任方 / 本版批准证据 / 允许用途 / 下游引用：…
~~~

## 消费与迁移

下游引用 seed_id + version + constraint_id，避免复制规则后各自修改。需要更新目标、权限或评价标准时返回修订建议，不在运行闭环中悄悄改写。
旧版没有类型、范围或批准记录时，先映射并标出缺口；不能仅改版本号就视为兼容或获批。
契约文件不可用或版本无法识别时，交付明确标注的草稿和依赖缺口，不推断生产可用性。
