# 测量、关联与实验

本文件维护数据口径、成熟窗口、健康线与实验设计细节；主文件只提供诊断流程。
根据产品使用节奏选择指标，以下 D_n 定义仅适用于确需按天衡量的场景。

## 事件与关联

| 数据 | 标识与粒度 | 注意事项 |
|---|---|---|
| 原始事件 | event_id；带 tenant_id、主体、event_time、ingested_at、事件版本 | event_id 在约定命名空间内唯一；重试 / 补发去重，区分事件时间与到达时间 |
| 任务执行 | task_id / run_id / trace_id | 一个任务可有多次尝试；不能把重试数当成功任务数 |
| 用户与身份映射 | 租户内 user_id，必要时有受控身份映射 | 跨设备合并、匿名转注册与删除需明确规则；不能跨租户误关联 |
| 实验暴露 | experiment_id、assignment_unit、arm、exposure_id / time | 区分被分配、实际暴露和进入分析；重复暴露不随意改变分组 |
| cohort | 由首次合格激活或业务约定事件派生 | cohort_week 是分组属性，不代替每个用户的起算时间 |
| 聚合结果 | 明确 tenant / cohort / 日期等粒度与主键 | 先按同一粒度聚合再关联；检查一对多 / 多对多导致的重复计数 |

不使用 user_id + ts + channel + cohort_week 作为通用连接键。
时间关联要定义窗口与多匹配裁决；渠道归因要固定模型、窗口和来源。检查连接前后的行数、唯一实体数及未匹配率。

## D_n 示例口径

- t0：用户首次合格激活的事件时间；时区固定为已选业务时区，并记录版本。
- 分母：目标 cohort 中满足观察成熟条件的首次激活去重用户；bot、内部账号等排除规则需预先说明。
- 分子：上述用户在 t0 对应本地日期加 n 天的窗口内出现合格事件的去重人数。
- 使用滚动留存、周留存或再次需求回访时另命名，不能与「恰好第 n 天」混用。
- 周 cohort 可以分组，但每人的窗口从自己的 t0 起算。
- 成熟要求：指标窗口已关闭，且达到预先定义的数据到达水位 / 延迟容忍期。D30 至少需要覆盖该窗口；新产品的 28 天数据不够。
- 同一张比较图优先使用完整成熟 cohort。若报告部分成熟人群，注明过滤后的分母与选择偏差，不能冒充完整 cohort。
- 数据删除、无法观测与确实未回访分开记录；缺失机制会影响解释。

口径变更需版本化、标注断点，必要时重算可比历史；不能悄悄替换，也不要求永远使用发现有错的旧定义。

## 健康线与样本不足

先检查可比性：相近人群 / 渠道、成熟窗口、季节性、产品和埋点版本。
多个可比成熟 cohort 的数量与样本规模由波动、检测目标和误报容忍度决定，不规定统一收集周数。

- 分位数报警需要足够且可比的历史分布，不将几个点的 P10 / P25 当稳定阈值。
- 留存率的不确定性依赖分母；不能对样本大小差异很大的比例使用同一固定标准差。
- 使用控制图前检查稳定性、季节性、过度离散与相关性；必要时使用适配比例数据的模型，而非直接套 3σ。
- 滚动窗口、每天反复查看与多分群会增加相关和多重比较问题；事先定义报警频率、确认条件和排查动作。
- 报警表示值得调查，不直接证明产品退化或某个原因成立。

样本不足仍可报告分子 / 分母、区间、描述性变化、病例和数据缺口；不能用「未显著」证明无效果。
区间方法与假设应注明，不凭少量数据制造精确概率。

## 实验设计

运行前明确实验是否在已获授权范围；设计实验不等于启动真实流量。

1. 写出因果假设和竞争解释，选择主要结果及护栏。
2. 确定随机 / 分配单位；考虑用户跨设备、同组织共享或其他干扰。
3. 根据基线、最小有意义效应、误差容忍度和可用流量估算样本，说明估计不确定性。
4. 运行时长覆盖真实使用周期和结果延迟；固定样本与序贯方法择一明确，不随意偷看后择时停止。
5. 写清异常数据处理、样本比例异常、重复实验及多指标处理。
6. 预先定义伤害停止与恢复；统计显著不能覆盖护栏失败。
7. 报告效应量、区间、样本、分群局限及未通过指标；只有授权和证据同时满足发布政策才发布。

没有足够流量时，可使用离线回放、案例核查或有限试点，但不要把它们包装成随机实验的因果证据。
