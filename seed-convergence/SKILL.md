# 种子收敛（Seed Convergence）

## 使用入口

用户可从一段经验、一个案例或已有种子开始。先说明本次要作出的决策与已有证据，选择最有影响的缺口推进。
用户要求一次性交付、限时访谈或不便提供材料时，尊重其范围，利用现有证据交付可用草稿。

## 工作原则

- 用户的总结、专业判断和案例都有价值，但证据性质不同。区分直接观察、用户陈述、分析推断与假设，不预设用户只会说口号。
- 用支持案例、失败案例和反例共同检查解释；提问不预设哪种答案正确。**要案例时优先要具体某一次（时间、谁、发生了什么），而非流程概括——概括只能定位，具体某次才暴露真实约束。**
- 资源、信息、激励、责任、结果可验证性是常用机制线索，不是穷尽分类。允许其他机制、复合机制和机制未明。
- 经验性判断检查证据和反例；规范性约束核对来源、违反条件与修订权限；目标写明取舍；策略比较替代方案。
- 优先减少会改变设计或风险判断的不确定性——**改变后损失大的先验证，便宜的快试错**——不以完成轮数、问题数量或分类命中作为成功标准。

## 推进方式

先把用户已有材料填入下表，区分「已有依据」「关键未知」「暂不影响本次决策」。
表中是覆盖维度，不是强制六轮。已有答案可跳过，发现冲突可回访，持续服务可使用观察周期。

| 维度 | 需要明确什么 | 缺失时的推进方式 |
|---|---|---|
| 边界 | 本次价值实现或观察周期，受益者、付费方及其他受影响方 | 先定能支持当前决策的范围，不强行讨论整个行业 |
| 价值 | 主要结果、底线、次级目标和冲突处理 | 用具体变化区分结果与代理指标；不排斥有意义的量化 |
| 结构 | 对象、参与者、状态、资源、责任与证据 | 用一个过程或案例检查缺失关系，容纳必要冗余 |
| 约束 | 类型、适用条件、依据和检查方式 | 追问机制或规范来源，区分「通常」「可能」「必须」 |
| 反馈 | 成功、失败、副作用、判据局限 | 查真实记录，标明观察与推断，不只搜集正向证据 |
| 验证与变更 | 新案例、竞争解释、变更条件与权限 | 记录未覆盖范围，避免凭单个例子宣布普遍成立 |

每次选择能最大程度改变结论的一组相关问题，数量随材料与用户时间调整。
重要边界、含义重解释和不可逆取舍需要回读确认；普通整理可随草稿供用户纠正，无需每步暂停。
如果连续追问没有增加信息，换证据来源、缩小判断范围或交付缺口，不重复施压。

## 常见分歧的处理

- 「必须当天响应」：分别查合同要求、用户损失机制和当前服务策略，不能混成一条。
- 「收入也是目标」：检查是否违反价值底线；允许在底线内同时优化成本、收入与用户结果。
- 「某次没遵守仍成功」：对经验性必要条件是反例线索；对法律或合同要求不能据此撤销。
- 「这条机制对谁不合适」：检查适用边界和副作用；若尚未发现反作用，写明检查范围，不为满足问法编造伤害。
- 用户回答矛盾：指出影响哪项判断；可先继续不依赖该矛盾的部分，避免冻结整个访谈。
- 无法提供案例：记为「当前证据不可得，原因待确认」；可能是保密、权限、遗忘或确实尚无记录，不推断企业阶段。

按需使用 [问题库](references/question-bank.md)；不要把库中所有问题依次问完。

## 产出与停止

交付种子的四部件、证据索引、假设 / 策略、缺口和下一步验证。边界不足或证据未闭合时也可交付草稿。
当关键缺口已得到回答、现有信息不再支持进一步推进，或达到用户约定的时间 / 范围时，结束本轮并说明剩余不确定性。

需要判断是否进入下一步时，可输出 next_action、关键缺口及依据、readiness（足够 / 有条件足够 / 不足）、允许推进的范围和补证条件。
先检查该动作不可替代的前提，再评估其他信息质量；不能用平均分掩盖关键缺口。缺少上线批准可能阻碍部署，却不必阻碍隔离原型设计。
readiness 是当前动作的信息充分度，不是种子的 validated / approved，也不授予操作权限。无校准依据时不用数值阈值制造精确性。
方法来源与效果证据边界见 [问题库](references/question-bank.md) 的下一步充分度部分。

正式交接的字段和状态统一读取 [种子契约](../seed-extraction/references/seed-contract.md)，不在本文件另建状态机。
如果只安装了本技能而契约不可用，使用「范围、价值、结构、约束、反馈、证据与缺口」交付 draft，说明尚不能确认正式交接状态；无需因此阻塞访谈或自动安装依赖。

支持证据与结构齐全不等于生产批准。用户已有授权可以在其范围内引用，不能由 Agent 自检生成授权。
用未参与提炼的案例检查时，明确它是真实保留案例还是构造场景；后者只检查逻辑边界。

## 示例

输入：「已有访谈和合同，今天只有十分钟，请整理客服种子。」

动作：从材料提取边界和合同约束，标记访谈陈述；只追问会改变服务承诺的缺口。
结果：带来源、条目类型、目标取舍和缺口的草稿，附最小验证动作，不重新从第一轮完整访谈。

## 分工与质量检查

seed-extraction 维护种子定义与交接契约；本技能负责交互；digital-life-service-design 负责服务结构；harness-design 负责运行机制；retention-diagnosis-loop 负责结果与运营反馈。
其他技能不可用时照常完成本次交互，记录交接缺口。
交付前检查是否重复问已有事实、诱导答案、误把规范当经验、把未知写成结论，或以用户未回答为由推断其业务状态。
